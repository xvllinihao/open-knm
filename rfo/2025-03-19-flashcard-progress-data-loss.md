# RFO: 单词记忆进度数据丢失

**日期:** 2025-03-19
**严重程度:** 高
**状态:** 数据无法恢复

## 概述

`flashcard_progress` 表中有 51 条用户学习进度记录被删除。由于 Supabase Free 计划没有自动备份功能，数据无法恢复。

## 时间线

- **2025-03-18 21:31** - 新记录创建 (IDs: 1, 4, 6)
- **2025-03-18 22:39** - 最后一条活跃记录创建 (ID: 55)
- **2025-03-19** - 发现仅剩 4 条记录 (IDs: 1, 4, 6, 55)

## 影响范围

| 表名 | 原有 | 剩余 | 丢失 |
|------|------|------|------|
| flashcard_progress | 55 | 4 | 51 条 |

- 约 50 名用户丢失了单词卡片学习进度
- `deck_ids`（已学习单词列表）和 `current_index`（当前位置）数据全部丢失
- 仅剩 1 名用户有实际进度数据

## 根本原因

1. **无备份策略** - Supabase Free 计划不提供自动备份
2. **迁移问题** - 数据库迁移可能删除/重建了表，未保留原有数据
3. **缺少容错逻辑** - 迁移脚本未使用 `IF NOT EXISTS` 检查

## 经验教训

1. **数据库变更前必须备份**
   ```sql
   CREATE TABLE backup_YYYYMMDD AS SELECT * FROM target_table;
   ```

2. **使用安全的迁移模式**
   ```sql
   -- 错误做法: DROP TABLE IF EXISTS ...
   -- 正确做法: ALTER TABLE ... ADD COLUMN IF NOT EXISTS ...
   ```

3. **免费计划没有安全保障** - 生产环境应用应考虑付费计划
